# Project State

## Current state summary (≤200 words)
WebDrop v2 is at **version 1.0.106**. The physical-proximity path uses a server-persisted runtime policy: score weights, minimum score, late-tap grace, acoustic window, and bump-time slop are editable from the admin **Settings** tab and snapshotted per session. The client requires an explicit server acknowledgement for final telemetry and the Azure hub logs structured rejection diagnostics without weakening the ultrasound+bump+tilt gate. Safari/iOS microphone access is no longer suppressed by a stale local denial. Production admin authentication now uses a visible, session-only **Admin access** form instead of a modal prompt; tokenless pages still load public readiness/policy data but do not request private diagnostics until the operator connects. The acoustic band is **17.8-19.8kHz** (4 concurrent lanes of 500 Hz), capped for 44.1kHz-device Nyquist safety so every lane emits on both 44.1 and 48kHz hardware (ADR-0021).

At the start of this session the working tree was effectively clean — the only pre-existing change in git status was an untracked `.cursor/mcp.json`. No application source files were mid-edit. Unit (`node --test`) and Playwright e2e suites exist; notable gaps: no coverage gate, no dedicated test for the data-channel transfer protocol, and live/relay e2e specs require the external server (see `tests.md`).

This `agent/` knowledge base was generated today from the real code as the standardized agent context for the repo.
